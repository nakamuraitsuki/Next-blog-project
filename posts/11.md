## 概要
---
ネットワークに関するかなり基礎的なところを勉強したので、忘れる前にちゃんとまとめておこうと思い画面に向かっています。

基本的には **「何を、どこに、どうやって」** についてまとめていきたいと考えています。

誤った図式、説明、解釈が多分に含まれる可能性がありますので、温かい目で見守ってください。

## 通信というものの全体概要
---
ネットワークの全体設計はOSI参照モデルに沿ったTCP/IPの階層モデルに従っています。

階層構造はアプリケーション設計などでもよく出てきますね。
それぞれの階層が自身に隣接しているところとだけ依存関係にあることで、開発・保守・拡張が容易になるというバカでかいメリットがあります。

## 「何を」送るのか
---
まずは通信の実体が何なのか見てみます。一番細かいところまで見ればビット配列なのですが、それをどういう単位で区切り、まとめ、取り扱っているかという話がしたいのです。

L7からL3の層では、通信でやり取りするデータの単位を **パケット**と呼びます。L2では **Ethernetフレームワーク**という呼び方をします。

先程紹介した階層構造では、それぞれの層が通信に必要な操作をしているわけです。それを可能にするためにデータに幾分かのメタ的データを付与しておく必要があります。

## L3 の「どこに」～IPアドレス～
---
説明の都合上、L3層の「どこに」から綴っていきます。

L3層では、**IPアドレス**を用いて相手を特定しています。

よく見られるのは`xxx.xxx.xxx.xxx`のような形の8bit x 4桁のような形式のIPv4です。

しかし、最近ではIPアドレス不足に対応するためにIPv6に移行する流れがあります。

### 効率よく管理するための「ネットワーク/ホスト」という考え方
もともとはIPアドレスは「クラス」という塊で管理されていました。
最初の8bitが同じIPアドレスをかためてクラスA、最初16bitが同じIPアドレスをかためて作ったクラスB、最初の24bitが同じIPアドレスを固めて作ったクラスCを用意していましたが，これはちょっと中途半端…

クラスAは所属するIPアドレスの数が多すぎる。クラスCはちょっと少ない。みたいな。

ちょうどいい大きさのクラスを扱うことが出来ないのは不便なので、IPアドレスを自由に **「ネットワーク部」** と **「ホスト部」** に分けることで、ちょうどよくIPアドレスをまとめられるようになっています。

これは「サブネットマスク」で表現され、
```bash
xxx.xxx.xxx.xxx/24
```
のようにIPアドレスの後ろに付して、先頭から何bitがネットワーク部（その集合で共通している部分）であるかを示しています。

ネットワーク部以外をホスト部といいます。以下のように特別な意味のあるホスト部があります。
```bash
xxx.xxx.xxx.000/24 # ホスト部が全部0 → そのネットワークの集合自体を示す
xxx.xxx.xxx.111/24 # ホスト部が全部1 → そのネットワーク集合内のすべてのIPにブロードキャストするときに使う
```

それ以外のホスト部はそれぞれ住所のように「どこへ」を示しています。

（後述の具体例を見ると、イメージがつかみやすいかもしれません）

### 特別なIPアドレス
基本的にはIPアドレスは **世界で唯一でなければいけません。**
そうしないと、正しくデータ（パケット）を届けられないからです。

（このように世界中で被りがなく、場所の特定に使えるIPアドレスをグローバルIPアドレスといいます）


しかし、実はIPアドレスの中には特別に、 **使いまわしを許されているIPアドレス** があります。
それらは、通信相手の特定としてそのまま使うことはできませんが
これを学びましょう。

1. **プライベートIPアドレス**
```bash
10.0.0.0 ～ 12.255.255.255
172.16.0.0 ～ 172.31.255.255
192.168.0.0 ～ 192.168.255.255
```
NAT技術と組み合わせることによって、これらのプライベートIPアドレスは非常に強力になります。

NATについては後述します。

2. ループバックアドレス
```bash
127.0.0.1 ～ 127.255.255.254
```
これは自分自身を指し示すためのIPアドレスです。

個人開発などをしたことがある方は、`localhost`という形で、このアドレスを見たことがあるかもしれません。

ここで取り上げた2つ以外にも、使いまわし可能なIPアドレスは存在します。（例示用IPアドレス等）

## L4 の「どこに」～ポート番号～
---
ひとつ前の項目で紹介したIPアドレスですが、これだけでパケットを完全に届けきることはできません。

データというのは、最終的に **デバイス間ではなく，アプリケーション間でやり取りしたいものなのです。**

データをしっかりアプリケーションまで届けるために、 **ポート番号** で「どこに」を指定します。

ポートとはざっくり言うとPCの入り口のことです。特定の入り口から入ってきたデータをそこに紐づけたシステムやアプリに渡します。

基本的に、一つのデバイスには65536個のポートが用意されています。そして、ポートはざっくり３つの種類に分けられます。

1. Well Known Ports (0～1023)

たとえばsshに22番ポート、http通信に80番ポート、といった風に一般的に利用されています。

（外部からの攻撃に備えて、あえてこの対応付けを変更することもできます。）

2. User Ports
Well Knownと違って、特別扱いはされていません。

8080や5173等に、開発中のアプリケーションを登録した経験がある方もいるかもしれません。

3. Dynamic Ports
特に割り当て、管理をしないことに決まっているポートです。
